Can your workflow
survive a replay?

Build a ticket follow-up list. Then send it duplicate events and old updates. Two rounds, fictional data, and a checkable answer.

Round 1

Make the current follow-up list

  1. Process an exact repeated event_id once.
  2. Use the greatest numeric revision for each ticket. Arrival order is irrelevant.
  3. Current Open → follow up. Closed → exclude. Blank or anything else → review.
  4. Conflicting copies of an event, or conflicting statuses at the same ticket revision, are input errors. Stop and resolve them.

Use a spreadsheet, no-code tool, script or AI assistant. Run the same input twice and compare the ticket lists.
